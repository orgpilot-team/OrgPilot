# بررسی نهایی معماری To-Be دیدراه

این پوشه نسخه یکپارچه و مستقل مستندات بررسی معماری است. فایل‌های پوشه منبع تغییر نکرده‌اند.

**وضعیت:** پیش‌نویس برای بررسی تیم

## فایل‌ها

### سند معماری

فایل [معماری To-Be](to-be-architecture.md) ساختار سیستم، جریان‌ها، داده، امنیت و نقش Agent را توضیح می‌دهد.

### رجیستر یکپارچه

فایل [رجیستر کنترل‌های معماری نسخه ۳](architecture-control-register-v3.md) با Tag ثابت `DIDRAH-ARCH-CONTROL-V3` مرجع فعال این موارد است:

- تصمیم‌های `ADR`
- موضوعات باز `DL`
- مسائل شواهد `REG-ISS`
- معیارهای پذیرش `AT`

هر رکورد فقط یک محل اصلی دارد. شناسه‌های قبلی حفظ شده‌اند.

فایل‌های `architecture-control-register.md` و `architecture-control-register-v2.md` فقط برای مقایسه و سابقه نگهداری می‌شوند.

### بریف پروژه

فایل [بریف فارسی پروژه](../دیدراه-بریف-دستیار-ایجنتیک-مدیران.md) مرجع نیازمندی‌ها است.

فایل [PDF هایلایت‌شده](دیدراه-بریف-۹۱-نیازمندی-هایلایت-و-کامنت.pdf) برای مرور دیداری نیازمندی‌ها است.

## ترتیب مطالعه

1. بریف پروژه را بخوانید.
2. سند معماری To-Be را بخوانید.
3. رجیستر یکپارچه را بر اساس موضوع کنترلی بررسی کنید.
4. ابتدا موضوعات `P0` را تعیین تکلیف کنید.
5. برای بستن هر موضوع، تصمیم، مالک، معیار پذیرش و شواهد را ثبت کنید.

## قاعده حاکمیت

رجیستر یکپارچه مرجع کار تیم در این پوشه است. فایل‌های منبع فقط برای کنترل سابقه و تطبیق محتوا استفاده می‌شوند.

تغییر وضعیت یک رکورد باید در رجیستر یکپارچه ثبت شود. موفقیت یک آزمون به‌تنهایی یک موضوع باز را نمی‌بندد.
