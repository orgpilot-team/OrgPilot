# Structurizr setup

Use `workspace.dsl` as the only DSL source and entry point. It contains the
proposed architecture.

`workspace.json` is a generated file. Structurizr uses it to keep manual
diagram layout information. Do not edit this file by hand.

## Prerequisites

Install Docker Desktop. Start Docker Desktop before you use the commands.

## Start the workspace

Run this command from the repository root in PowerShell:

```powershell
docker run --rm -it -p 8080:8080 -v "${PWD}/architecture/structurizr:/usr/local/structurizr" structurizr/structurizr local
```

Open <http://localhost:8080>.

Stop the local server with `Ctrl+C`.

If port 8080 is in use, use port 9090:

```powershell
docker run --rm -it -p 9090:9090 -e PORT=9090 -v "${PWD}/architecture/structurizr:/usr/local/structurizr" structurizr/structurizr local
```

Then, open <http://localhost:9090>.

## Validate a change

Use the Structurizr CLI before you commit a DSL change:

```powershell
docker run --rm -v "${PWD}/architecture/structurizr:/usr/local/structurizr" structurizr/structurizr validate -workspace /usr/local/structurizr/workspace.dsl
```

A successful command returns without a validation error.

## Edit the architecture

1. Edit `workspace.dsl`.
2. Save the file.
3. Refresh the browser.
4. Validate the file.
5. Commit `workspace.dsl` and `workspace.json` together when you change a
   manual diagram layout.

Keep stable view keys. Structurizr uses these keys to copy layout information
from `workspace.json` when it reloads `workspace.dsl`.

## Troubleshooting

- If the browser shows the old model, stop the container and start it again.
- If Docker cannot mount the directory, enable file sharing for drive `D:` in
  Docker Desktop.
- If the page is not available, confirm that the container is running and that
  the selected port is free.
- If a diagram loses its layout, confirm that its view key did not change.
- Do not delete `workspace.json` only to fix a DSL syntax error. First, run the
  validation command and correct `workspace.dsl`.
